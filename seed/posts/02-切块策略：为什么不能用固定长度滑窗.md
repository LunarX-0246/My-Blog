# 切块策略：为什么不能用固定长度滑窗

几乎所有 RAG 教程的第一步都是这句：

```python
splitter = RecursiveCharacterTextSplitter(chunk_size=400, chunk_overlap=40)
chunks = splitter.split_text(raw_text)
```

对纯散文这没问题。但技术博客不是散文，照这么切会持续地损坏内容。

## 滑窗切坏的三样东西

### 代码块被从中间截断

一段 30 行的 Python 代码，按 400 字符切，会变成两三个碎片。
检索命中其中一片时，模型看到的是半个函数 —— 上半截没有返回值，
下半截没有函数签名。它要么答不出来，要么开始猜。

更糟的是这种损坏**看不出来**：召回分数正常，回答也通顺，只是内容是错的。

### 表格被腰斩

```
| 方案 | 召回 | 延迟 |
|---|---|---|
| 纯向量 | 中 | 低 |
```

从中间切开后，前半块有表头没数据，后半块有数据没表头。
后半块被单独召回时，模型完全不知道那几列是什么意思。

### 标题路径丢失

这是最隐蔽的一条。一个块被切出来后就脱离了原文，
里面的「它」「这个方法」「上面提到的」**全部失去指代**。

滑窗的 overlap 想解决的就是这个问题，但 40 个字符的重叠远远不够 ——
真正需要的上下文是「这段话属于哪一节」，而那可能在几百行之前。

## 按标题层级切

Markdown 自带结构，直接用它：

```
一篇文章 → 按 ## 和 ### 切开 → 每块超长时再按段落二次切
```

切分时守住两条：**代码围栏（```）内部不切**，**表格不切**。
实现上就是按空行分段时，遇到围栏起始就一路吃到围栏结束。

```python
def _split_paragraphs_keep_fences(text):
    """按空行切段落，但代码围栏内部不切。"""
    in_fence = False
    for line in text.split("\n"):
        if line.strip().startswith("```"):
            in_fence = not in_fence
        # 只有不在围栏里，空行才是分段点
        if not in_fence and line.strip() == "":
            yield_current_paragraph()
```

## 上下文前缀：最便宜的语境补偿

每个块在送去向量化之前，**拼上它的标题路径**：

```
实际存的正文：
  RRF 的公式是 score = Σ 1/(k + rank)...

送去 embedding 的文本：
  混合检索：向量与 BM25 的融合 > RRF：怎么把两路结果合起来
  RRF 的公式是 score = Σ 1/(k + rank)...
```

前面那串等于告诉模型「这段话出自什么背景」。不用调 LLM 生成摘要，
纯字符串拼接，**对召回质量的提升却非常明显**。

知识库文档同理，前缀里再加上目录路径：

```
八斗学院/week10-RAG > RAG 讲义 > 混合检索 > 为什么需要 BM25
```

## 块要携带定位信息

引用能跳回原文，靠的是每个块记录了自己在原文里的位置：

| 内容类型 | 记录什么 | 引用跳到哪 |
|---|---|---|
| 文章 | 标题锚点 | `/posts/{slug}#锚点` |
| PDF | **页码** | `/docs/{id}?page=N` |
| Markdown / txt 文档 | 块序号 | `/docs/{id}#chunk-N` |

PDF 那一列尤其要注意：**必须按页解析**，返回 `[(page_no, text)]`。
常见写法是把所有页拼成一个 `raw_text` 再切，
**页码在拼接的那一刻就永久丢失了**，后面再想跳页码就没有依据了。

## 短内容不必切

一篇两三百字的短笔记，本身就是一个完整语义单元。
硬按标题切反而会切出「只有一个标题、正文两句话」的碎块，
这种块的向量几乎不携带信息，只会污染检索结果。

判断标准很简单：**块的正文短于某个阈值时，与上一块合并**。
